Сайт: https://botstore-kz-market.ra1k0n.chatgpt.site

Репозиторий: https://github.com/ramadanurk-commits/BotStore

Питч на казахском: [rk1-defense-kk.md](rk1-defense-kk.md). План — 4:45 выступления и 2 минуты ответов. Все три участника говорят. Презентация помогает рассказу; продукт показываем по живой ссылке.

## Что сделать до занятия

1. Открыть сайт и войти в админку владельцем. Открыть «Заявки на услуги». Проверить индикатор базы и кнопку «Открыть статус API».
2. Во втором окне открыть публичный сайт. Подготовить форму помощи с установкой, но не отправлять заранее. Имя `[TEST] РК1 демо`, контакт `rk1-demo@example.test`, сообщение не короче 10 символов, согласие отмечено. Это синтетические тестовые данные.
3. Вместе пройти демо: отправить форму → скопировать ID → найти заявку в админке → перезагрузить страницу → снова найти по ID. Убедиться, что статус поиска «Все».
4. Показать GitHub: README, серверный код и настоящие коммиты участников. Вписать имена двух остальных участников в README. Каждый делает и объясняет собственные реальные изменения со своего аккаунта.
5. Один раз провести полный питч с таймером. Не превышать 5 минут; после него остаётся 2 минуты вопросов.

Можно войти через ChatGPT или email/пароль. Владелец подключает почтовый вход из существующего аккаунта через «Подключить вход по email». Покупки и права сохраняются. Публичный каталог и форма заявки доступны без регистрации. Восстановление почтового входа — по личному коду, без отправки писем. Код импортирован и подготовлен с помощью Codex; это не заменяет личные коммиты участников.

## Новая функция для демонстрации

Поиск заявок работает на сервере, а не только по уже загруженным карточкам. Он находит имя, контакт, ID и текст обращения, совмещается со статусом и находит старые записи, даже если они не вошли в последние 200. Специальные символы `%`, `_`, `\` не превращаются в маски поиска.

Индикатор базы не показывает зелёный статус заранее. Он делает запрос `GET /api/health`, сервер выполняет `SELECT 1` в D1. Только успешный ответ даёт состояние «База данных подключена». Кнопка повторяет проверку; рядом доступен сам JSON API.

## Как объяснить код своими словами

| Часть | Файл | Объяснение |
| --- | --- | --- |
| Форма | `app/sales.tsx` | Пользователь заполняет данные, браузер отправляет POST |
| Админские заявки | `app/service-requests.tsx` | `q` и `status` отправляются через URLSearchParams; ответ отображается в карточках |
| Сервер | `lib/sales-api.ts` | Проверяет пользователя, параметры и сохраняет/читает заявки через SQL |
| База | `lib/db.ts`, `drizzle/` | D1 binding `DB`, схема таблиц и миграции |
| Проверка соединения | `lib/api.ts` | `/api/health` проверяет настоящую базу, возвращает 200 или 503 |
| Надёжность | `tests/backend-persistence.mjs` | Записывает заявку в отдельную базу, перезапускает Worker, читает ту же запись |
| Поиск и доступ | `tests/api.integration.mjs` | Проверяет поиск, ограничения, чужие данные и старые записи |

Если спрашивают «это localStorage?»: заявки хранятся в D1 на сервере. Локально в браузере хранится только часть предпочтений, например выбор товаров для сравнения.

Если спрашивают «ноутбук выключим?»: сайт опубликован в Cloudflare Workers, D1 хранится в облаке; наш локальный процесс ему не нужен. Купленные Telegram-боты — отдельные шаблоны, которым покупатель настраивает токен и постоянную среду запуска.

Если спрашивают «откуда прибыль?»: комиссия 15% — текущая настройка модели. Пример в презентации является расчётным сценарием, а не реальным доходом. Платные продажи сейчас отключены; автоматический банковский платёж не подключён.

## Быстрое практическое изменение

- Подписи поиска и индикатора: `lib/sales-i18n.ts`. Значения идут в порядке казахский / русский / английский. Измените все три перевода и объясните, где они используются.
- Вид списка и поля поиска: `app/service-requests.tsx`, `app/service-requests.css`.
- Логика поиска: блок `GET service-requests` в `lib/sales-api.ts`. Значения передаются через `.bind(...)`; пользовательский текст не вставляется в SQL.
- Статусы заявки должны совпадать в сервере и интерфейсе. Значение «Все» применяется только к фильтру, его нельзя сохранять как статус заявки.

На компьютере с установленным Node.js и зависимостями проверки запускаются так:

```powershell
npm run typecheck
npm run test:api
npm run test:backend
```

Демо не требует запуска локального сайта. Проверки используют отдельную базу; они не создают платежи и заявки реальных клиентов.

При ошибке соединения покажите её честно и проверьте интернет/API. Не выдавайте сохранённый скриншот или расчёт прибыли за работающую функцию или реальную выручку.
