# BotStore: объяснение новой функции для трёх участников

**Зачем сравнение:** предприниматель выбирает подходящую автоматизацию.
Цена сама по себе не показывает, нужен ли Python, Google-аккаунт или постоянный
сервер. Сравнение помогает увидеть эти требования до покупки.

Общая цепочка: **каталог → выбранные ID → проверка и сохранение → актуальные
товары → таблица → карточка товара → существующее оформление заказа**.
Сравнение не создаёт заказ и не подтверждает оплату.

## Участник 1: выбор и интеграция

Откройте `app/store.tsx` и `app/comparison.tsx`.

- `Store` получает товары с `/api/bootstrap` и вызывает `useComparison`.
- `CompareButton` получает товар, язык, признаки выбранного товара и достижения
  лимита. По нажатию вызывает `onToggle(product.id)`.
- Для выбранного товара кнопка остаётся доступной, даже когда уже выбрано три.
  Поэтому можно убрать один и выбрать другой.
- `aria-pressed` сообщает пользователям клавиатуры и экранного диктора состояние.
- `ComparisonTray` показывает названия, счётчик, удаление и очистку списка.
  С одним товаром предлагает выбрать второй; кнопка перехода пока выключена.
- `#compare` переключает экран приложения. Из таблицы товар открывается тем же
  `openProduct`, что используется каталогом: покупка проходит существующие проверки.

**Можно объяснить своими словами:** «Моя зона ответственности — элементы выбора
и связь с каталогом. Кнопка передаёт ID товара в общую логику, поэтому каталог,
карточка товара и панель показывают одно состояние. Сравнение доступно гостю,
а оформление покупки использует обычный защищённый процесс».
Называйте личным вкладом только выполненные и проверенные вами изменения.

**Возможные вопросы:**

1. Почему не хранится отдельный список в каждой карточке? — Списки разошлись бы;
   одно состояние в hook связывает все элементы.
2. Что произойдёт при нажатии на уже выбранный товар? — Его ID удаляется.
3. Почему сравнение не требует входа? — Это просмотр публичных товаров.
4. Где изменение покупок? — В этой функции его нет; открывается существующая карточка.

**Репетиция:** добавьте кнопки сравнения в `BusinessPacks` из `app/sales.tsx`,
передав состояние и обработчик через props. Проверьте, что выбор в блоке пакетов
и в основном каталоге совпадает. Текст «В сравнении» также должен совпадать.

## Участник 2: данные, ограничения и сохранение

Откройте `lib/comparison.ts`, `hooks/use-comparison.ts` и `tests/comparison.test.mjs`.

- `COMPARISON_LIMIT` — общий лимит, сейчас 3. Число используется логикой и интерфейсом.
- `normalizeComparisonIds` принимает неизвестное значение и проверяет, что это
  массив. Оставляет непустые строковые ID, удаляет повторения и ограничивает длину.
  При переданном наборе `available` исключает отсутствующие товары.
- `readSavedComparison` безопасно читает JSON: повреждённые данные превращаются
  в пустой выбор. Слишком большие значения также игнорируются.
- `toggleComparisonId` возвращает **новый** массив. Добавляет или удаляет товар,
  не изменяя предыдущий массив состояния.
- `comparisonProducts` соединяет сохранённые ID с текущим каталогом. В браузере
  не сохраняются старые цены и описания, поэтому таблица использует актуальные данные.
- `useComparison` читает localStorage после загрузки компонента в браузере.
  Во время серверного отображения localStorage недоступен.
- Проверка на удалённые товары начинается только после успешного bootstrap.
  Временная загрузка или ошибка API не должна стирать сохранённый выбор.
- После изменения ID сохраняются. Если браузер запретил хранилище, выбор остаётся
  в памяти текущей страницы, а экран объясняет ограничение.
- Событие `storage` обновляет выбор при изменении в другой вкладке.

**Можно объяснить:** «Я отвечаю за правильность и сохранение выбора. Мы храним
только ID: при открытии соединяем их с актуальными товарами. Повторы, неизвестные
ID и повреждённый JSON не ломают сайт. Лимит проверяется в логике, поэтому одной
выключенной кнопкой защита не ограничивается».

**Возможные вопросы:**

1. localStorage — это база сайта? — Нет, это данные одного браузера; на другом
   устройстве выбор автоматически не появляется.
2. Почему `try/catch`? — Хранилище может быть запрещено, а JSON повреждён.
3. Почему только ID? — Чтобы не показывать сохранённые устаревшие цены.
4. Почему не менять массив через `push`? — React ожидает новое состояние,
   прежние значения должны оставаться неизменными.
5. Что если товар снят с публикации? — После обновления каталога его ID удаляется.

**Репетиция:** измените лимит на 2, запустите тест и обновите ожидания именно для
нового требования. Убедитесь, что счётчик и добавление следуют одной константе.
После упражнения верните 3: это лимит готовой функции, а не личное улучшение ради коммита.

## Участник 3: таблица, языки и мобильный экран

Откройте `ComparisonPage` в `app/comparison.tsx`, `lib/comparison-i18n.ts` и
блок `Product comparison` в `app/globals.css`.

- Каждая колонка — выбранный товар; каждая строка — цена, тип, описание, состав,
  требования или файл.
- `product.content[lang]` выбирает описание на текущем языке.
- `translate(lang, key)` выбирает подпись интерфейса. Для каждой новой подписи
  заполнены казахский, русский и английский варианты.
- Цена форматируется через `Intl.NumberFormat`; нулевая цена отображается как «Бесплатно».
- Возможности разделяются по переносам строк и отображаются списком.
- React отображает текст безопасно; описания не вставляются как произвольный HTML.
- Семантические `table`, `th scope="col"` и `th scope="row"` связывают заголовки
  с данными. Контейнер таблицы доступен с клавиатуры через `tabIndex={0}`.
- На телефоне таблица имеет минимальную ширину и прокручивается внутри своего
  контейнера. Остальная страница не должна становиться шире экрана.
- С нулём товаров показывается понятное пустое состояние и переход в каталог.

**Можно объяснить:** «Я отвечаю за понятное сравнение. Пользователь видит не
только стоимость, но и необходимые аккаунты и оборудование. Смена языка меняет
подписи и товарные данные. На телефоне сохраняется таблица, которую можно
прокрутить, а из любой колонки открывается соответствующий товар».

**Возможные вопросы:**

1. Откуда цены? — Из текущего ответа каталога, не из localStorage.
2. Почему на телефоне есть прокрутка? — Две-три колонки с требованиями должны
   оставаться читаемыми; уменьшение текста до нескольких пикселей не подходит.
3. Как добавить новую строку? — Добавить подпись в трёх языках, `tr` с `th` и
   по одной ячейке для каждого выбранного товара.
4. Можно ли скачать файл прямо из таблицы без покупки? — Нет; она открывает товар,
   доступ к файлу проверяет сервер после оформления.

**Репетиция:** добавьте в таблицу строку «Количество возможностей» с подсчётом
непустых строк в `features`. Переведите подпись и проверьте разные товары.
Объясните, что большое число возможностей само по себе не доказывает лучшее качество.

## Общая демонстрация на 3–4 минуты

1. **Участник 1:** за 45–60 секунд показать выбор двух-трёх товаров, счётчик,
   удаление и переход к сравнению.
2. **Участник 2:** за 45–60 секунд перезагрузить страницу, объяснить ID,
   актуальные цены и ограничение трёх товаров, открыть функцию нормализации.
3. **Участник 3:** за 45–60 секунд показать языки, требования и мобильную таблицу,
   открыть один товар.
4. **Все:** открыть GitHub, показать собственные коммиты и коротко объяснить
   конкретные изменения каждого. Не выдавать коммиты Codex за личные.

## По-казахски: короткая репетиция

**1:** «Менің жауапты бөлігім — тауарларды таңдау және каталогпен байланыстыру.
Пайдаланушы үш тауарға дейін қосып, біреуін алып тастай алады. Барлық батырма бір
таңдау күйін пайдаланады. Салыстыру үшін аккаунтқа кіру қажет емес».

**2:** «Мен таңдау логикасын түсіндіремін. Браузерде тек тауарлардың ID-і сақталады.
Баға мен сипаттама ағымдағы каталогтан алынады. Қайталанатын және қолжетімсіз
тауарлар алынып тасталады. Бет жаңарған кезде таңдау сақталады».

**3:** «Менің жауапты бөлігім — салыстыру кестесі, тілдер және телефондағы көрініс.
Пайдаланушы бағаны, мүмкіндіктерді және орнату талаптарын қатар көреді. Интерфейс
қазақша, орысша және ағылшынша жұмыс істейді. Кестеден тауарды ашып, сатып алу
бөліміне өтуге болады».

Тек шынымен орындап, тексерген өзгерістерді жеке үлес ретінде атаңыз.
