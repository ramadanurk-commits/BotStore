# BotStore: команда из трёх человек: запуск и защита

Готовая новая функция: **сравнение до трёх решений для бизнеса** по цене,
возможностям, требованиям для установки и файлу. Работает на казахском, русском
и английском, без обязательного входа. Выбор сохраняется в браузере.

## Запустить на компьютере

1. Установите Node.js **24 LTS**: https://nodejs.org/en/download . Для проекта
   подходит Node.js 22.13 или новее. Закройте и снова откройте VS Code после установки.
2. Распакуйте весь архив. В VS Code откройте папку `BotStore`, где лежит `package.json`.
3. В Terminal → New Terminal выполните:

```sh
node scripts/desktop-start.mjs
```

На Windows можно открыть `START-BOTSTORE.cmd` двойным кликом.
Первый запуск скачивает закреплённые зависимости, применяет пять миграций и
добавляет девять стартовых товаров. Нужен интернет. Повторный запуск сохраняет
местные заказы и изменения. Браузер: **http://127.0.0.1:5173** .
Остановка: Ctrl+C. Терминал должен оставаться открытым.

Кнопка «Войти» на localhost использует тестового администратора `seedy@sites.test`,
без пароля и ChatGPT. Это встроенный режим разработки, он не входит в production-
сборку. Локальная база отдельная: покупателей, заказов, настроек и ZIP-файлов,
загруженных на рабочий сайт, в архиве нет. Встроенные шаблоны есть.

Если `node` не распознан, сначала установите Node.js и полностью перезапустите
VS Code. Проверка: `node --version`. Не удаляйте lock-файл при ошибке загрузки
зависимостей: проверьте интернет и повторите запуск.

## Разделить ответственность

| Участник | Часть | Основные файлы |
| --- | --- | --- |
| 1 — Райымбек | Выбор, кнопки, панель выбранных товаров и интеграция с каталогом | `app/store.tsx`; `CompareButton` и `ComparisonTray` в `app/comparison.tsx` |
| 2 | Ограничения, сохранение выбора, удалённые товары | `lib/comparison.ts`, `hooks/use-comparison.ts` |
| 3 | Таблица, языки, переход к товару, адаптация для телефона | `ComparisonPage` в `app/comparison.tsx`, `lib/comparison-i18n.ts`, стили comparison в `app/globals.css` |

Код подготовлен с помощью Codex. Это распределение зон ответственности.
Каждый должен прочитать, проверить и уметь изменять свою часть; личные коммиты
должны подтверждать реально выполненную им работу. Коммиты Codex не являются
тремя личными коммитами каждого участника. Вымышленные авторы и даты не добавлены.

Подробное объяснение, вопросы и репетиция: **[docs/team-defense.md](docs/team-defense.md)**.

## Подготовить общий GitHub

Установите Git, если VS Code его не видит: https://git-scm.com/downloads .
Общий репозиторий уже создан: https://github.com/ramadanurk-commits/BotStore .
Повторно создавать репозиторий или инициализировать Git в клонированной папке не нужно.
Клонируйте его через VS Code → **Git: Clone** или командами из
[инструкции VS Code / Vercel](docs/vercel-vscode.md).

В GitHub: Settings → Collaborators → Add people. Приглашайте реальные логины
участников, каждый принимает приглашение и делает свои изменения/коммиты.

`.gitignore` исключает зависимости, локальную базу и реальные `.env`/`.dev.vars`.
Файлы `.env.example` и `.dev.vars.example` — безопасные примеры.

## Реальные задачи для личных коммитов

Базовое сравнение уже готово. Если начинаете работу с этого пакета, делайте
свои изменения поверх него. Ниже — девять самостоятельных полезных улучшений;
они **не реализованы автоматически** и не отмечены как ваша выполненная работа.
Каждый коммит делайте после реализации и проверки одного законченного этапа.

| Участник | Три последовательных изменения | Пример названия коммита |
| --- | --- | --- |
| 1 | Добавить выбор для карточек бизнес-пакетов на главной | `Add comparison controls to business bundles` |
| 1 | Показывать номер выбранного товара на карточке, как в таблице | `Show comparison order on selected cards` |
| 1 | Добавить переход из панели выбора сразу к требованиям в таблице | `Link comparison tray to setup requirements` |
| 2 | Добавить тест восстановления сохранённого выбора после обновления каталога | `Test saved comparison against catalog changes` |
| 2 | Добавить функцию формирования ссылки на сравнение с проверкой ID | `Generate validated comparison links` |
| 2 | Восстанавливать выбор по такой ссылке, проверять неизвестные и повторные ID | `Restore shared comparisons from valid catalog IDs` |
| 3 | Добавить сортировку колонок по цене с сохранением правильных заголовков | `Sort comparison columns by price` |
| 3 | Добавить переключатель «Только отличия» для одинаковых строк | `Show only differing comparison attributes` |
| 3 | Добавить переводимые состояния и проверку этих двух новых режимов | `Localize and test comparison display modes` |

Тест должен проверять конкретный сценарий или ошибку. Изменение только цвета,
пробела или сообщения коммита не считается новым содержательным вкладом.

Перед сохранением коммита проверьте изменения в Source Control. Настройка автора
в своей копии, если Git запросит её: используйте **собственные** имя и email.
Не используйте чужие данные, чтобы создать видимость работы команды.

## Проверить готовую функцию

```sh
npx --yes pnpm@11.25.0 typecheck
npx --yes pnpm@11.25.0 test:comparison
```

Сценарий для демонстрации:

1. Открыть каталог без входа и выбрать два разных товара.
2. Добавить третий: четвёртый выбрать нельзя, выбранный убрать можно.
3. Нажать «Сравнение». Показать стоимость, состав и требования.
4. Переключить язык: весь экран и данные переключаются.
5. Открыть товар из таблицы: существующая покупка работает через обычные проверки.
6. Перезагрузить страницу: выбор сохраняется. Очистить список и показать пустое состояние.
7. На узком экране прокрутить таблицу горизонтально. Она также прокручивается с клавиатуры.

TypeScript и автоматические проверки логики/серверного отображения выполнены.
Интерактивная браузерная проверка и запуск на Windows отдельно не выполнены.
Проверьте сценарий выше на своём компьютере до защиты.

## Что показать преподавателю

- Рабочий сайт и новую функцию сравнения, полезную покупателям BotStore.
- Общий GitHub с доступом у всех троих и минимум тремя **личными** содержательными
  коммитами каждого, сделанными в период задания.
- У каждого: конкретное изменение, его код и объяснение пользы покупателю.
- Готовность изменить свою часть: репетиционные задания находятся в памятке.

Перенос исходников в GitHub не копирует production-базу или секреты. Email/пароль
уже реализованы; текущий Site также поддерживает ChatGPT. Для Vercel подготовлен
Next.js gateway с тем же API/D1/R2, без доверия к внешним заголовкам идентичности.
Публикация на Vercel требует доступной команды и защищённой серверной переменной.
Подробности и список файлов для защиты: [docs/vercel-vscode.md](docs/vercel-vscode.md).
